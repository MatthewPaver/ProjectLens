# Design Context — ProjectLens change assurance

## Target audience
Programme / project controls reviewers and PMO leads preparing a board or change committee pack. Secondary audience: hiring managers assessing whether Matthew builds serious, evidence-bound tools (not chatbot demos).

## Use cases
1. Load previous + current Primavera P6 XER (bundled Northstar demo or bring-your-own).
2. Read deterministic blockers (finish slip, contradictions, unexplained change).
3. Optionally retrieve cited precedents via the local RAG sidecar (Gemini + LangGraph, LangSmith traces).
4. Mark each precedent Use or Ignore (human gate).
5. Record a decision with conditions — the system never decides.

## Brand personality / tone
Editorial programme assurance. Contradiction-first headlines. Calm authority, not startup hype. Trust comes from readable evidence, honest boundaries, and a visible human gate — never from “AI approved this.”

## Aesthetic direction
- **Tone:** industrial editorial — Archivo Black display, tinted paper/ink neutrals, restrained accent (sand / assurance tokens).
- **Not:** purple gradients, Inter, IBM Plex Mono, thick side stripes, neon “AI” chrome.
- **Mono:** JetBrains Mono only for codes/scores — labels stay readable (≥11px).
- **RAG surface:** Gemini brief must be high-contrast; hybrid score + semantic decimal labelled separately; weak matches &lt;0.80 flagged.
- **Pages vs local:** GitHub Pages is static (XER + offline precedent cards). Live hybrid retrieve is local `make precedent-rag` unless `PROJECTLENS_PRECEDENT_RAG_URL` is set.

## Absolute bans (Impeccable)
- No `border-left` / `border-right` accent stripes &gt;1px
- No gradient text
- No banned default fonts (Inter, IBM Plex, Space Grotesk, etc.)
- No pure black / pure white — keep tinted neutrals

## Differentiation
The product voice is the blocker headline pattern (“finish moved N days but the narrative presents stability”) plus citations-only briefs that refuse to invent DG-* ids.
